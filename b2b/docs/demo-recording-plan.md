2026-09-10 15:45 EDT. Planning only while video capture is paused for concurrent Blender work. No new audio, scene changes, requests, recordings or media retrieval in this session.

## Narrative and problem

**Founder hook:** “I used to DJ.” The user saw the Ableton Rickroll and the dog-bark spectrogram example, and wondered what Astra could do with music.

**Problem:** Choosing good songs is personal; turning those choices into a coherent set requires decisions about fit, order, entry, and how long to overlap. Matching tempo alone does not answer those questions.

**Experiment:** Can Astra reason over measured track evidence and the user's musical direction well enough to propose a set worth listening to?

**Human role:** The user supplies the crate, directs taste, reviews notes, auditions transitions and can take over the real mixer. Treat “good” as a judgment to demonstrate by listening, not an objective model score.

**Payoff:** One complete handoff is audible; a request decision shows the same musical direction matters when the set changes. The animated DJ makes the performance visible while the music plays.

Recommended story: curiosity → build → musical decision → audible test → request → human control. Alternative opening: start with the mix, then rewind to inspiration; stronger immediate sound, but weaker fit with the user's requested personal origin. Alternative emphasis: request-first; useful for a longer demo but adds setup before the music. Use the origin-led cut.

## Features to show, with priorities

1. **One complete, good-sounding mix.** Mandatory; reserve the uninterrupted 16-second core. Use the actual master output, not a soundtrack laid over silent UI. Verify the incoming track keeps playing and the audio handoff sounds right.
2. **User's crate and Astra's plan/taste notes.** Mandatory; show the causal link between selected songs, one musical reason and the transition we hear. A useful reason includes a choice and its musical consequence. Show the real returned wording rather than authoring a stronger fake quote.
3. **One request assessment.** Strong supporting proof. Show one coherent accept/reject/review outcome. Avoid a second download or a long search flow. The rejected comedy-track example is concise; an accepted request is a backup if its queue placement is clearer in the current UI.
4. **Watch the set.** Keep the Astra-built DJ/scene visible during real playback. It should be driven by current mixer state. The scene is a development achievement; the model is not regenerating or puppeteering a 3D character at runtime unless separately established.
5. **Manual takeover.** A short ending proves human control, especially after the algorithmic decisions.
6. **Upload analysis.** Show the resulting BPM/key/phrase map briefly. The wait, upload picker and detailed corrections belong in the longer version; a fresh import is not necessary to explain every-upload analysis.

Leave effects menus, full library imports, extended grid editing, every request status, architecture diagrams and whole-set playback out of this minute. They remain useful supporting documentation or finalist-demo material.
